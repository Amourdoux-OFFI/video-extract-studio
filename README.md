# Video Extract Studio

一个**完全在本机运行**的 Windows 桌面视频工具：把抖音 / B站的分享文本整段粘进来，
批量解析并下载视频，并直接完成裁剪、压缩与水印区域处理。输出统一为 mp4。

无需注册、无需上传、不依赖任何在线服务，也没有任何遥测。

> ⚠️ **使用前请务必阅读 [法律与责任声明](#法律与责任声明)。**
> 本工具仅面向个人学习与研究用途。下载他人作品、去除权利标识、二次传播的合法性
> 取决于你所在地区的法律与平台条款，责任由使用者自行承担。

## 特性

### 解析下载
- **整段粘贴即可**：分享文本里的 `2.05 复制打开抖音…`、`:5pm 03/04 l@C.hb` 这类
  杂乱前后缀会被自动忽略，只提取链接；一次可粘多条，也支持只有裸链接。
- **支持形式**
  - 抖音：`v.douyin.com/xxxx`、`douyin.com/video/123…`、混合在分享文本里
  - B站：`b23.tv/xxxx`、`bilibili.com/video/BVxxxx`、含 `?p=N` 的多 P 链接
- **多清晰度选择**：抖音 1080P / 720P / 540P；B站 1080P / 720P / 480P / 360P
- **批量并发**：多链接并行解析、多任务并行下载，实时显示进度、速度与剩余时间
- **断点续传**：多连接分片下载，CDN 主地址失败自动切备用地址
- **本地导入**：拖拽文件或文件夹，支持 mp4 / mkv / mov / avi / flv / webm / ts 等

### 剪辑压缩
| 功能 | 说明 |
|---|---|
| 智能裁剪 | 优先无损切割并吸附最近关键帧；偏差超过 1.5 秒自动转帧精确，避免黑帧 |
| 强制无损 | `-c copy`，秒级完成、零画质损失 |
| 帧精确 | 重新编码，切割点完全准确，CRF 18 视觉无损 |
| 保画质压缩 | CRF 三档预设 + 可选分辨率限制，**保证不会把文件压得更大** |
| 目标体积 | 两遍 ABR 编码，按指定 MB 输出 |
| 水印区域处理 | 自动检测 + 手动画框，插值修复 / 模糊 / 马赛克，支持时间分段 |
| 硬件加速 | 自动检测 NVIDIA 显卡并使用 NVENC（实测比 x264 快约 30%） |
| 其他 | 静音、体积预估、处理前后对比、内置播放器预览 |

## 快速开始

### 方式一：下载免安装成品

到 [Releases](../../releases) 下载 `VideoExtractor-*.zip`，解压后双击
`VideoExtractor.exe`。自带 Python 运行时与 FFmpeg，**目标机器无需安装任何东西**。

> 仓库本身只有约 **0.5 MB**（纯源码）。FFmpeg 二进制（158 MB）与构建产物不进仓库：
> 前者用脚本拉取，后者放 Releases。

### 方式二：从源码运行

```bash
git clone https://github.com/Amourdoux-OFFI/video-extract-studio.git
cd video-extract-studio

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

python tools/fetch_ffmpeg.py          # 拉取 FFmpeg / FFprobe（必需，约 60 MB 下载）

start.bat                             # 启动（无控制台窗口）
start-console.bat                     # 启动（带控制台，便于排错）
```

`tools/fetch_ffmpeg.py` 只用标准库，从 npmmirror 拉取官方静态构建，国内通常能跑满带宽。
也可以自行安装系统级 FFmpeg，程序会自动从 `PATH` 找到它。

### 方式三：自己打包 exe

```bash
.venv\Scripts\python tools\build.py
```

产物在 `dist/VideoExtractor/`，约 228 MB（主要是内置的两个 FFmpeg 可执行文件）。

## 使用

### 解析下载
1. 打开「解析下载」标签页，把分享文本整段粘进去
2. 点「开始解析」，等结果卡片出现（封面 / 标题 / 作者 / 时长 / 平台）
3. 在卡片里选画质（B站还需选音轨），勾选要下载的条目
4. 点「下载选中」，在底部任务面板看进度

### 剪辑压缩
1. 选择文件（可直接用刚下载的，也可从电脑导入）
2. **裁剪**：拖双滑块或输入起止秒数，有「设为当前播放位置」按钮；
   时间条上会标出关键帧位置，智能模式会自动吸附并提示误差
3. **压缩**：选模式与档位；勾选硬件加速可大幅提速
4. 点「预估输出」看体积对比，再点「开始处理」

输出统一落在 `output/`。

## 技术说明

以下结论均来自实测，不是推测。仓库里的 `tools/probe_*.py` 就是当时用的验证脚本。

### 抖音：无水印源在哪个字段

水印**不是烧在源文件里**的，而是同一份源视频在带水印的地址上被服务端实时叠加。
关键在于取哪一路：

```
v.douyin.com/xxxx  --302-->  iesdouyin.com/share/video/{aweme_id}
  → 签名请求 www.douyin.com/aweme/v1/web/aweme/detail/     （需 a_bogus 签名）
  → 取 video.bit_rate[] 中 format=mp4 且码率最高的一档
  → 下载时带上 Referer: https://www.douyin.com/           （否则 403）
```

同一作品两路对照实测：

| 来源字段 | 分辨率 | 体积 | 水印 |
|---|---|---|---|
| `video.bit_rate[]` 最高档 | **1920×1080** | 17.67 MB | **无** |
| `video.download_addr` | 1280×720 | 20.20 MB | 有（logo + 抖音号 + 作者名） |

> 注意体积是反常的：带水印那一路分辨率更低、体积却更大，这是水印转码的典型特征。

详情接口需要 `a_bogus` 签名，裸请求会被 `ArgusSecurityPlugin` 拦截返回空，
因此签名与 Token 生成交给 [f2](https://github.com/Johnserf-Seed/f2) 完成。
实测**游客状态即可**，无需登录。

### B站：一个被忽视的画质开关 `try_look`

网上普遍认为 B站 `playurl` 需要 WBI 签名。本项目对 10 种请求组合做了对照实验，
结论出人意料：

| 请求姿势 | 拿到的画质档位 |
|---|---|
| 免签名（原始） | `[32,16]` → 854×434 / 640×324 |
| **免签名 + `try_look=1` + `fnver=0`** | **`[80,64,32,16]` → 1920×976 / 1280×650 / 854×434 / 640×324** |
| WBI 签名（带不带 `try_look` 都一样） | `[32,16]` |
| 再叠加 `buvid3` Cookie | 无变化 |

**`try_look` 才是解锁高码率档位的开关，与是否签名无关。** 未登录即可拿到 1080P。
本项目把它作为主路，WBI 签名退居兜底。

其他要点：
- DASH 每个档位含 3 套编码（AVC `codecid=7` / HEVC `12` / AV1 `13`），默认优先 AVC 保兼容
- CDN 分片**必须带 Referer**，否则 403
- 1080P60 / 4K / 8K 及杜比、无损音轨需要大会员；本项目**不绕过付费内容**

### 剪辑：能不重编码就不重编码

| 场景 | 做法 | 耗时量级 |
|---|---|---|
| 只裁剪 + 智能/强制无损 | `-c copy` | 秒级 |
| 只裁剪 + 帧精确 | 仅重编码，CRF 18 | 与视频等长 |
| 开了压缩（CRF） | **受限 CRF**：`-crf N -maxrate {源码率}` | 与视频等长 |
| 目标体积 | 两遍 ABR | 约两倍时长 |

**为什么压缩要用「受限 CRF」**：纯 CRF 在源码率本就很低的视频上会**把文件压得更大**。
实测 14.6 MB 的源，CRF21 重编码后变成 17.1 MB，NVENC 更是涨到 25.6 MB。
加上 `-maxrate` 把输出码率钳在源码率之下后就正常了：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| CRF21 | 14.6 → **17.1 MB** | 14.6 → **12.6 MB** |
| NVENC | 14.6 → **25.6 MB** | 14.6 → **13.2 MB** |

### B站水印：为什么只能后期处理

B站在转码时会叠加**投稿水印**（UP主昵称 + `bilibili` logo），位置由上传者设置决定，
因此每个视频都不同；部分视频还有会**移动**的第二处水印。

**换码流规避这条路是走不通的。** 对同一稿件穷举全部可获取码流并逐条抓帧比对：

| 码流 | 条数 | 结果 |
|---|---|---|
| DASH 4 档清晰度 × 3 种编码 | 12 | **全部带水印** |
| `fnval=1` durl 单文件 | 1 | 带水印 |
| `platform=html5` | 1 | 带水印 |
| TV 端接口 | — | 返回 `-400`，取不到 |

14 条全部带水印，且水印随分辨率等比缩放。平台不提供无水印的转码产物。

因此本项目做的是**后期处理**：

- **自动检测**：水印是白色半透明文字 → 每帧都「近白且低饱和」。采样 60 帧统计
  每个像素的跨帧持续性，画面里会移动的白色物体（云、衣服、灯光）自然被排除。
  亮度/饱和度阈值走**三档自适应**，兼顾「压在白墙上」与「压在亮色天空上」。
- **去除**：优先 `delogo`（用周围像素插值，画质最好）；贴边区域缺少邻域像素，
  自动改用模糊 / 马赛克。
- **移动水印**：一键**定时扫描**按间隔自动取样并生成限时区域，也可拖时间轴手动逐点补充。

> **能力边界**：水印烧在像素里，去除本质是插值猜测，**不可能无损**。
> 背景越复杂痕迹越明显，这是原理限制，任何工具都一样。

### 踩过的坑（值得记录）

1. **`delogo` 的 `enable` 用的是输出时间轴。**
   ffmpeg 只要用了 `-ss`（无论放在 `-i` 前还是后），时间戳都会重置为从 0 开始，
   于是「一边裁剪一边按时间窗去水印」会整体错位。对照实验：把时间窗设成 66~82s，
   在 t=74s 处差异为 **0.00**（没生效）；设成 0~10s 反而差异 **1.30**（生效了）。
   修法是所有水印时间窗统一减去起始偏移。

2. **`f2` 会在当前工作目录凭空建 `logs/`。**
   `f2/log/logger.py` 写死 `Path("./logs")` 并在 **import 时**就 `mkdir()`，
   路径相对 CWD。从别的目录启动程序就会污染那里。
   修法：在 import f2 之前先给 `"f2"` logger 挂上自己的 handler ——
   f2 的 `log_setup()` 开头有 `if logger.hasHandlers(): return`，于是不再建目录。

3. **yt-dlp 的 `cookiesfrombrowser` 会硬失败。**
   Chrome 数据库被占用时直接抛错终止。改为「先带 Cookie 试，失败自动去掉 Cookie 重试」。

4. **水印检测不能用「帧 − 全片时域中值」。**
   多场景视频里中值本身就是几个镜头的混合，差异会被镜头切换淹没。
   改用「近白掩膜的跨帧持续性」才稳定。

```

```

## 常见问题

**Q：抖音解析偶尔失败？**
抖音接口有风控。程序已做游客 Token 自愈重试与请求限速（串行 + 最小间隔）；
若持续失败，可在「设置」里填入浏览器登录后的抖音 Cookie 提高成功率。

**Q：B站只能下 480P？**
正常情况下未登录可拿到 1080P（靠 `try_look`）。若某些稿件受限，在「设置」里填入
B站 Cookie 后重试。1080P60 / 4K / 8K 需要大会员，本工具不绕过。

**Q：输出为什么比原来大？**
正常情况下不会 —— 程序会把码率钳在源码率之下。若提示「源码率已很低」，
说明该视频已经压得很充分，建议提高 CRF 或勾选限制分辨率。

**Q：无损裁剪的切割点不准？**
无损切割只能切在关键帧上。程序会自动吸附并提示误差，超过 1.5 秒自动改用帧精确模式。

**Q：程序联网吗？会读我的 Cookie 吗？**
只在点击解析/下载时访问对应平台及其 CDN。没有任何数据上传，没有遥测。
「浏览器 Cookie 读取」是可选项（默认关闭），开启后只在本机读取并只用于对应平台的请求，
不会外发；你也可以改为手动粘贴 Cookie。

**Q：NVENC 选项是灰的？**
没检测到可用的 NVIDIA 编码器。程序会实际试跑一次编码确认驱动可用，而不是只看编码器列表。
